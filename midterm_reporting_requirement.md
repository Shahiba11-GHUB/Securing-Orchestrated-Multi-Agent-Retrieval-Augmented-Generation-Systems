# Midterm Reporting Requirement

This document defines what must be completed and shown by the midterm checkpoint.

## 1) Scope and problem framing

- Finalized project scope
- Finalized problem statement
- This scope/problem document completed and agreed upon

## 2) Core system implementation status

- Working RAG pipeline
- Basic orchestrator with **2–3 agents**

## 3) Dataset and protocol readiness

- BIPIA dataset loaded
- BIPIA usage/integration documented
- Written evaluation protocol

## 4) Baselines and comparisons

- Clean vs. attacked baseline results
- At least two comparison points:
  - No defense
  - Keyword filter
- First version of trust-aware defense implemented/evaluated

## 5) Quantitative results

- Results table with real numeric outcomes (not placeholders)

## 6) Failure analysis deliverables

- At least **20** selected cases for failure analysis
- Cases grouped into at least **3** categories
- At least **5** cases written up in detail

## 7) One depth analysis

Complete one deeper experiment/analysis track:

- Preferred options:
  - Single-agent vs. multi-agent, or
  - Isolated memory vs. shared memory
- Fallback option if memory experiment is not ready:
  - Retrieval configuration and top-k sensitivity analysis

## 8) Communication artifacts

- High-level architecture diagram
- A **3–5 minute demo** that includes:
  - One input
  - One successful result
  - One failure case
  - What comes next (next-step plan)

## Midterm completion checklist

- [ ] Scope and problem statement finalized
- [ ] RAG pipeline working
- [ ] Orchestrator working with 2–3 agents
- [ ] BIPIA loaded and documented
- [ ] Evaluation protocol written
- [ ] Clean vs. attacked baseline results produced
- [ ] No-defense baseline reported
- [ ] Keyword-filter baseline reported
- [ ] Trust-aware defense v1 reported
- [ ] Results table populated with real numbers
- [ ] 20+ failure cases selected
- [ ] Failure cases grouped into 3+ categories
- [ ] 5 detailed failure write-ups completed
- [ ] One depth analysis completed
- [ ] High-level architecture diagram prepared
- [ ] 3–5 minute demo prepared
